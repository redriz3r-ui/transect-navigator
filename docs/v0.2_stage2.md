# v0.2 Stage 2 — survey setup and batch PREPARE

Stage 2 is an additive scripting/integration baseline. The verified v0.1 single-
transect UI, schemas, exports, CRS guards and calculation engines remain unchanged.
There is no Survey UI, recording intake, assignment or batch analysis in this stage.

## Survey and plan model

`survey/model.py` defines immutable `Survey` and `PlannedTransect` records plus an
explicit process-local `SurveyRegistry`. Durable identity is exported in the survey
package; it is not hidden in a global registry.

A Survey records:

- exact `Survey_ID`, name, schema version and timezone-aware creation instant;
- semantic and exact-serialization plan snapshot digests;
- exact official source CRS WKT, normalized PROJ definition and authority ID;
- optional display CRS metadata, source schema, ID-field name and plan revision;
- every registered planned transect, including unsupported plans.

A planned-transect record carries `(Survey_ID, Transect_ID)`, original provider
feature key for traceability, a portable content key, exact geometry WKB, tagged
native attributes, exact and normalized CRS definitions, official source direction,
revision, and separate navigation/QA-model status and length fields. Provider FIDs
and QGIS layer IDs are not portable identities. Original columns are neither renamed
nor overwritten; Survey identity remains in metadata, so legacy Waypoint_ID values
stay human-readable.

## Setup and preflight

`setup_survey()` snapshots the complete official layer; project selection is ignored.
It rejects an empty layer, missing ID field, blank/NULL/nonfinite IDs and IDs that
collide after the existing trimmed-text normalization. Registration is atomic. An
identity failure raises `SurveyPreflightError` with diagnostics for every feature.

Every plan is independently checked by the unchanged PREPARE adapter and existing
v0.1 local QA working-path rules. Multipart, curved, Z/M, empty, invalid-coordinate,
zero-length, dynamic-CRS and out-of-model cases are retained with explicit status and
reason. Navigation eligibility is separate from QA-model eligibility: for example,
a long line may be navigable while exceeding the existing 5 km QA radius. Unsupported
navigation plans cannot disappear silently; `prepare_survey_navigation()` requires a
nonblank exclusion reason for each omitted Transect_ID and retains it in the manifest.

The source snapshot digest covers CRS meaning, schema, geometry, typed attributes,
feature multiplicity and order-independent content. Mutable FIDs and layer names are
excluded. The exact original FID is retained separately as a trace key.

## CRS snapshot and provenance policy

QGIS 4.2.3 can normalize a custom projected CRS while creating a memory layer. In the
final static custom-CRS fixture it removes the optional nested EPSG:9122 angular-unit
annotation; the original failure probe based on the WGS 84 datum also removed nested
EPSG:7030. Geometry, attributes, units and the operation are unchanged. A GeoPackage
round trip can normalize authority annotations again.

The implementation therefore separates:

- **live semantic equality:** QGIS/PROJ CRS equality for source-to-memory snapshots;
- **operational definition:** normalized PROJ definition, with only metadata token
  `+type=crs` removed, plus matching CRS type, units and axis order for provider
  round trips;
- **serialization provenance:** exact official QGIS WKT and a separate serialization
  digest stored in Survey and plan metadata.

A WKT string difference alone is not treated as mutation. A changed projection
parameter, datum/ellipsoid definition, units, CRS type or axis order remains a failure.
The implementation neither substitutes another CRS nor relaxes the v0.1 dynamic-CRS,
fallback-transform, geographic-unit or coordinate-validity guards.

## Batch PREPARE

`prepare_survey_navigation()` calls the existing `integration/prepare.py` batch
adapter, which in turn uses the unchanged `navigation/waypoints.py` engine. It creates
waypoints for all included valid plans atomically. Sequence resets for each Transect_ID;
both endpoints, configured spacing, short final intervals and forward bearing behavior
remain unchanged. Official geometry remains in source order. `reverse=True` is an
explicit navigation operation and does not modify the official snapshot.

Example for QGIS Python scripting:

```python
registry = SurveyRegistry()
setup = setup_survey(
    planned_layer,
    "Transect_ID",
    survey_id="SURVEY-2026-01",
    name="Wildlife survey",
    registry=registry,
    plan_revision="1",
    project=QgsProject.instance(),
)
navigation = prepare_survey_navigation(
    setup,
    spacing_m=10.0,
    project=QgsProject.instance(),
)
folder = export_survey_navigation(
    navigation,
    output_parent,
    "survey_navigation",
)
```

## Survey navigation export

Export stages and verifies all content before exclusive publication and never replaces
an existing package. `survey_navigation.gpkg` contains:

- `planned_transects`: included official geometries, native CRS and original fields;
- `navigation_waypoints`: unchanged legacy WGS84 waypoint schema;
- `surveys`: identity, schema, digests, CRS provenance and revision;
- `plan_manifest`: every registered plan, including excluded/unsupported plans;
- `navigation_run`: spacing, reverse flag, model and software provenance.

`survey_manifest.json` mirrors machine-readable metadata. Optional standard companion
files remain the existing CSV, GeoJSON and valid GPX outputs. Package README text makes
the Survey_ID namespace explicit; companion waypoint IDs are intentionally unchanged.
All GIS layers are reopened through QGIS, counts/fields/values/geometries/CRS are
verified, SQLite integrity checks run, and standard companions use the existing
validators before publication.

## Synthetic fixture and validation

`samples/survey_prepare` contains twelve independent eastward 100 m WGS84 equatorial
transects with original Team/Priority fields and an intentionally conflicting source
field named Survey_ID. At 10 m spacing the expected result is 132 waypoints: 11 per
line, sequence 1–11, station 0–100 m, 90° forward bearing and final NULL bearing.
The fixture is PREPARE-only and does not replace SYN01.

Stage 2 tests cover batch equivalence with the legacy adapter; configurable/reverse
spacing; identity validation; unsupported geometry and explicit exclusion; semantic
and exact CRS provenance; metre and US-foot custom projected input; source immutability;
stable content IDs; all companion formats; GeoPackage reopen; failed-write cleanup;
and no-overwrite behavior.

The completed QGIS 4.2.3/macOS regression run contains **314 passing tests, zero
failures, zero errors and zero skips**. All 287 Stage 1 test identities remain present;
Stage 2 adds 27 tests.

## Known limitations

- Stage 2 has scripting/integration entry points only; existing v0.1 UI remains intact.
- Registry state is process-local until exported. Resume/edit workflows belong to a
  later stage.
- One spacing and reverse setting applies to the included batch; per-plan overrides
  are intentionally deferred.
- Unsupported plans require explicit exclusion for navigation export. The package
  retains their metadata/WKB but standard companions contain included plans only.
- Exact official CRS provenance is the representation exposed by QGIS, not original
  bytes from an external datasource definition.
- Existing 100,000-waypoint and geometry/CRS/model limits still apply.
- There is no recording intake, surveyor registry, segmentation, assignment,
  association, batch QA, results aggregation or Survey UI yet.

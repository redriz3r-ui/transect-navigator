# v0.2 Stage 3 — immutable multi-file recording intake

Stage 3 adds Survey-level recording intake and persistence around the existing v0.1
GPX/CSV/QGIS-layer parsers. It does not associate observations with transects, join
recordings, infer surveyors, construct continuity beyond source structural groups, or
run QA. The verified single-transect UI and engines remain unchanged.

## Source and recording model

`survey/intake.py` defines portable records for sources, recordings, raw-observation
index rows, normalized working rows and import attempts. `integration/survey_intake.py`
owns detached QGIS snapshots and bounded source bytes.

A `Source_ID` hashes `(identity version, Survey_ID, stable content identity)`. File
content identity is the SHA-256 of the exact bounded byte snapshot parsed. Loaded
layers use an order/FID/name-independent native content and semantic-CRS digest. A
renamed byte-identical file therefore resolves to the existing source. A duplicate
attempt remains in the import ledger but creates no second recording or observation.

A `Recording_ID` hashes `(identity version, Source_ID, recording key)`. CSV has one
recording, each supported OGR sublayer is separate, and each GPX track is a separate
recording whose segments remain explicit structural groups. `Surveyor_ID` is nullable
and only user supplied. It is never inferred from coordinates, times or filenames.

An `Observation_ID` hashes `(identity version, Recording_ID, original observation
key)`. GPX trackpoint and CSV row keys come from the one-read parser snapshot. File
provider feature keys are namespaced by immutable file content. Loaded layers use a
portable feature-content/occurrence key while retaining provider FID separately as a
trace key. GeoPackage output FIDs and mutable QGIS layer IDs are never identities.

## Raw and normalized data

Each accepted recording retains an independent native observation snapshot and, when
supplied, an independent native track snapshot. Original fields, values, geometry,
CRS, Z/M and structural groups remain unchanged; collision-safe v0.1 provenance fields
remain additional fields. Original file bytes are retained in memory until saved and
archived by hash under `sources/`. A loaded layer is represented honestly as a native
snapshot because original device bytes are unavailable.

Normalized rows are derived and linked one-to-one by `Observation_ID`. They contain
WGS84 working coordinates where a strict transform succeeds, exact original timestamp
text, nullable UTC time, separate time/position validity, source order and mapped raw
GNSS values. Missing, invalid and duplicate times remain represented. An optional IANA
timezone can normalize unambiguous naive ISO timestamps; ambiguous/nonexistent local
times remain invalid. Accuracy, HDOP and PDOP keep raw values and unknown units. Blank
accuracy is NULL, never zero, and dilution values are not treated as metre radii.

Invalid geometry or CRS can remain as a raw observation with a NULL working position.
Preservation and downstream analyzability are separate. No chronology, smoothing,
snapping, cross-file track or transect relationship is invented.

## Duplicate, overlap and failure semantics

Exact source content is accepted once per Survey. Reimports, including renamed files,
are `DUPLICATE` attempts referencing the original `Source_ID`. Nonidentical sources
with at least two exact coordinate-and-original-time matches (or a matching singleton)
are retained independently and marked `SUSPECTED_OVERLAP`; nothing is merged or
deleted. Equal coordinates with different timestamps are legitimate and are not a
duplicate signal.

Every attempt is recorded. Existing bytes that fail parsing become a `FAILED` source
with error and checksum; an absent/unreadable request remains a failed ledger attempt.
A multi-sublayer file can be `PARTIAL`, retaining valid recordings and explicit failed
recording rows. Survey totals report `SUCCESS`, `PARTIAL`, `FAILED` or `EMPTY`; one
failed source never erases accepted sources.

Existing 50 MiB/100,000-observation per-input limits remain. Stage 3 adds limits of
100 accepted sources, 1,000 recordings, 1,000,000 observations and 500 MiB of captured
file bytes per in-memory Survey. Intake is synchronous and does not access QGIS
providers from worker threads.

## Persistence and interface

`save_survey_intake()` publishes a new, verified standard package directory and refuses
overwrite. `survey_intake.gpkg` contains `sources`, `recordings`,
`raw_observation_index`, `normalized_observations`, `import_attempts` and separate
native raw layers per accepted recording. `survey_intake_manifest.json` is the typed
portable manifest; `sources/` contains verified original bytes when available.
`load_survey_intake()` requires the same Survey and plan snapshot, verifies hashes,
counts and identities, removes only writer-created provider row-ID fields, and restores
detached native snapshots. Failed and duplicate attempts survive close/reopen.

`SurveyRecordingsPanel` is the utilitarian Survey-workspace component for selecting
multiple files or a loaded layer, inspecting format/status/count/time/CRS/errors,
editing nullable `Surveyor_ID`, and saving/reopening intake. CSV requires explicit XY
and CRS. The component is intentionally additive; the current v0.1 `MainDialog` is not
replaced before the broader Survey workspace exists.

## Supported inputs and limitations

- GPX 1.0/1.1 tracks/trackpoints through the existing strict UTF-8 parser;
- explicit-coordinate UTF-8 CSV;
- every supported point/line GeoPackage or GeoJSON vector sublayer;
- supported loaded QGIS point/line layers.

Unsupported sublayers are visible as failed recording rows. GPX routes and standalone
waypoints remain in archived bytes but are not recording observations. A singleton GPX
segment is retained in bytes and structural metadata but cannot form a LineString.
Loaded-layer identity describes the captured snapshot, not original device bytes.
Source bytes plus native QGIS layers are retained in memory until saved, so large jobs
have a deliberate memory cost. Stage 4 will consume these records for reviewed
continuity and assignment; Stage 3 contains no assignment state.

The Stage 3 focused QGIS tests cover multiple formats/files/tracks/surveyors, duplicate
and overlap semantics, failures/partial imports, mixed CRS, timestamp/timezone states,
GNSS fields, native Z geometry, stable identities/order, structural GPX segments,
raw preservation, save/reopen, overwrite protection, totals and the recordings panel.

# Stage 7 — auditable Survey snapshot export

Stage 7 adds an evidence package for one **current, analyst-reviewed** Survey state.
It does not assign GPS observations, change the v0.1 QA engines, or define scientific
compliance. In Survey RESULTS, build current results and choose **EXPORT AUDITABLE
SURVEY…**. Select a parent directory and a new package name. An existing name is
refused, even if its contents look incomplete. The export is staged in a sibling
temporary directory, reopened and verified, then exclusively published. A failure
removes staging and leaves existing packages intact.

```text
new_package/
  survey_analysis.gpkg
  survey_summary.csv
  transect_summary.csv
  source_manifest.csv
  metadata.json
  README.txt
  sources/                 # exact original bytes, when Stage 3 retained them
```

The GeoPackage is the authoritative relational and spatial copy; CSV files are flat
convenience views. Every record table includes stable portable identity columns and
`record_json` for its complete typed content. GeoPackage-generated FIDs are never
used as identities. `metadata.json` records snapshot ID/time, Survey/plan/review/Visit/
QA/results dependencies, policy, QA settings, software/schema version, counts,
layer digests/CRS, and SHA-256 hashes of all data files. Its hashes detect accidental
change, not malicious forgery; the package is not cryptographically signed.

## Authoritative content and relationships

| Group | GeoPackage layers/tables | Meaning |
| --- | --- | --- |
| Plan | `surveys`, `plan_manifest`, `planned_transects`, optional `navigation_run` and `navigation_waypoints` | Full Survey/plan record; native-CRS WKB copy; navigation is included only when supplied to the export API. |
| Intake | `surveyors`, `sources`, `recordings`, `import_attempts`, `raw_observation_index`, `normalized_observations`, `raw_observations_*`, optional native track layers | Original source schema/geometry and every imported observation, including invalid-for-QA observations. |
| Review | `continuity_segments`, `segment_membership`, `assignment_membership`, `assignment_decisions`, `decision_membership`, `visits`, `visit_membership` | Explicit source/recording segmentation, one effective disposition per Observation_ID, append-only decisions, ordered exact memberships. |
| QA | `analysis_runs`, `visit_qa`, `transect_qa`, `qa_observations`, `qa_events`, `qa_event_geometry_*` | Accepted Visit results and dependencies. QA point geometry is a derived WGS84 view; event geometry is in that Visit's local metric CRS. |
| Results | `completion_policy`, `evidence_scopes`, `transect_results`, `survey_summary`, `project_status`, `export_runs` | Explicit policy/relevance history, one result and copied map geometry per official line, project totals, immutable export identity. |

`plan_manifest` retains original source-attribute JSON and WKB/CRS provenance;
`planned_transects` is its native-CRS spatial copy. `raw_observation_index` maps each
Observation_ID to Source_ID, Recording_ID, source order, native geometry/attribute
digests and original keys. Each recording's `raw_observations_*` layer retains native
attributes and geometry, including Z when the provider supports it. Identical native
features are reconciled as a multiset to the raw index, since provider FIDs may change.
No original GPS field or geometry is replaced by the derived normalized/QA view.

Every retained raw Observation_ID appears once in normalized observations and once in
effective assignment membership, whether ASSIGNED, AMBIGUOUS or UNASSIGNED. Activity
roles preserve SURVEY, TRANSITION and UNKNOWN; missing/invalid times and unknown
surveyors remain explicit. Ordered segment, decision and Visit memberships are separate
edge tables. Successful Visit QA observations must have valid Visit, source, recording, plan
and raw-observation provenance. Unresolved evidence and relevance scopes remain in
the package rather than being discarded when calculating QA. `qa_events` links to
metric geometry layers by Event_UID; stationary events use SQL NULL geometry, while
moving events retain LineString WKB.

## Source bytes and CRS

For file imports, `sources/` contains the retained original bytes, named with their
SHA-256 plus a safe original basename. `source_manifest.csv` records Source_ID,
original name/path metadata, exported path, format, import status, surveyor codes and
checksum. A renamed duplicate is recorded as an import attempt, not a second source.
For loaded QGIS layers with no original file bytes, the manifest says
`UNAVAILABLE_LOADED_LAYER`, gives no invented source file, and retains the native
snapshot and its digest. Source bytes are rehashed before copying and after writing.
The export fails on mismatch. A hash is provenance/integrity evidence, not proof that
the original device logged accurate positions.

Original plan and native recording layers retain their own CRS. Working QA observation
points are WGS84. Event lines retain the v0.1/Stage 5 local metric analysis CRS.
The standalone verifier reopens every layer through QGIS, checks CRS equivalence,
WKB/NULL geometry, row counts, portable identities, source bytes and relationships.
Custom/projected CRS acceptance follows the existing Stage 2 CRS contract; this
stage does not silently reproject original geometry to make an export appear valid.

## CURRENT and stale results

Only a CURRENT Stage 6 result with matching plan, intake, review, QA, completion policy
and evidence-scope dependencies can be exported. If any input or setting changes,
the UI disables export and asks for the affected QA/results computation to be rerun.
No stale result is published as current. `metadata.json`, `export_runs` and the CSV
summary mark a verified export `CURRENT` **at creation time**; they do not claim the
package tracks later changes to an external project. This stage does not export a
separate stale archival package.

The completion policy is an analyst-selected operational progress/endpoints rule.
COMPLETE and other statuses do not certify ecological or regulatory compliance.
Accepted track length is travel within accepted Visits; observed progress is the
gap-limited station-support union; QA-corridor support further applies user-configured
deviation classes. Repeated Visits cannot make support exceed planned length. GNSS
accuracy remains reported uncertainty and is never subtracted from deviation.

## Verification and limitations

`verify_survey_snapshot(path)` is a standalone read-only verifier requiring PyQGIS.
The exporter runs it before publication. It checks GeoPackage integrity, required
layers, counts, record/geometry digests, CSV-to-GeoPackage key summary values,
raw/normalized/assignment reconciliation, ordered memberships, Visit/QA/event
provenance, QA point coordinates, status-map attributes, source checksums, status counts
and key project totals. Missing/corrupt
content raises an error. This is a snapshot interchange package, not an automatic
re-analysis or a replacement for review history and original field files.

The UI presently exports without optional navigation waypoints because the Survey
RESULTS workspace does not retain a navigation-run object. The export API can include
a current Stage 2 navigation snapshot; absence is explicit in metadata, not implied
to mean no waypoints were ever generated. Very large exports remain synchronous and
need field-scale performance testing. QGIS/PROJ/provider versions and all source
operations are documented in the stored QA context and CRS records, but actual
portability across other QGIS installations and real device datasets remains to be
validated. No Stage 8 full 12-transect fixture or automated assignment is included.

See [the focused fixture](../samples/survey_snapshot/README.md). Under configured
QGIS Python, run `python3 -m unittest tests.qgis.test_survey_snapshot_export` or
`python3 -m unittest discover -s tests -t .` from the repository root.

On QGIS 4.2.3/macOS, the unchanged Stage 6 baseline was **435 passed, 0 failed,
0 errors, 0 skipped**. The final Stage 7 suite was **451 passed, 0 failed,
0 errors, 0 skipped**; 16 new PyQGIS tests passed. A fixture package including
11 sources and 94 raw fixes exported and reopened in **2.579 s** in the final run. Its package size
was **1,505,195 bytes**, of which **6,910 bytes** were copied source files. These are
small-fixture timings, not a scale estimate for a 10 × 10 km field Survey. Qt
offscreen font/window warnings were nonfatal. No real mouse-driven QGIS GUI session
or cross-platform/device-file acceptance was claimed for Stage 7.

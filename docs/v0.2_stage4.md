## Continuity policy

The analyst explicitly chooses positive maximum time and spatial gaps. The dialog
offers 60 seconds and 100 metres for review, requiring confirmation before a run is
created. These are operational break settings, **not ecological compliance standards**.
A break occurs when a gap is strictly greater than its limit; equality does not break.
Parameters are frozen in the review snapshot and in decision provenance.

Each Source/Recording has independent structure and its own externally supplied,
nullable Surveyor_ID. No cross-recording or cross-file joins are possible. Consecutive
structural runs preserve GPX segment boundaries, including a repeated segment key
after an intervening segment. Validated temporal gaps, nonincreasing instants, spatial
jumps, time-validity changes, invalid positions and reviewed cuts create boundaries.
Every retained point is present exactly once in the segment partition, including
points unusable for QA. Invalid positions are isolated and cannot be accepted.

Distances use `QgsDistanceArea` with WGS84 ellipsoid and the Stage 3 normalized WGS84
working coordinates. They are not Euclidean calculations on latitude/longitude.
Native raw coordinates, fields, timestamps and snapshots are unchanged.

A structural run has `UTC_SOURCE_ORDER` only if all timestamps are aware/valid,
unique and strictly increasing in source order. Missing, duplicate or reversed time
keeps the run `SOURCE_ORDER_ONLY`. No time interpolation or guessed sorting occurs.
The existing intake duplicate-time flags are respected conservatively, including
duplicates flagged across structural segments in a recording. The run's original
timestamps remain inspectable; segment/Visit start and end times are NULL when
chronology is unsupported. Valid pairs may still identify a gap within such a run,
but that does **not** recover chronology for the remaining pieces.

Chronology-unknown points may be manually assigned for later point QA. Stage 5 must
not infer time-based events, supported track length or coverage from their storage
order. A separate speed/impossible-movement heuristic is not implemented; the explicit
time and spatial limits are the Stage 4 break policy. Stops are not deleted.

## Assignment, decisions and Visits

Every retained Observation_ID starts `UNASSIGNED / UNKNOWN /
INSUFFICIENT_EVIDENCE` with no decision. Selecting rows alone does not confirm them.
The analyst must provide reviewer identity and a reason for every mutation.

Actions use exact Observation_ID lists, never an inferred timestamp range:

- **ASSIGN / REVISE**: one official Transect_ID, `ASSIGNED / SURVEY`, and explicitly
  chosen `FORWARD`, `REVERSE`, `MIXED` or `UNKNOWN` direction.
- **TRANSITION**: `UNASSIGNED / TRANSITION`, no accepted transect.
- **AMBIGUOUS**: `AMBIGUOUS / UNKNOWN`, no forced tie-break or accepted transect.
- **UNASSIGNED**: `UNASSIGNED / UNKNOWN`, no accepted transect.
- **SPLIT BEFORE SELECTED ROW**: one exact observation anchors a reviewed boundary;
  existing dispositions stay unchanged. Multiple cuts can be made separately.

Manual decisions use `REVIEWER_CONFIRMED`: this confirms the analyst's disposition,
including a decision to leave uncertainty unresolved. It is not a probability or
evidence that GPS established intention. This stage does not emit `RULE_SUPPORTED`
or candidate-derived confidence labels. Ambiguity can remain indefinitely.

Every action appends a Decision_ID/revision with UTC, reviewer, reason, exact membership,
run/input/parameter identity and superseded disposition Decision_IDs. Partial edits
leave earlier decisions intact. Replay reconstructs the effective membership from
the complete history. A reviewed split appends a boundary action; it does not rewrite
the original continuity evidence. There is no merge/remove-cut action in this stage.

Visits are maximal consecutive accepted members of a single decision within a single
continuity segment. A different decision, transition, ambiguous/unassigned point, gap,
structural boundary or reviewed cut splits the Visit. Selecting nonadjacent rows never
bridges the intervening excluded observations. Repeated/partial work is valid; no
endpoint requirement or completion classification is applied. Visits retain source,
recording, nullable surveyor, segment, decision, exact ordered IDs and direction.
Official planned geometry is never reversed. Direction is a reviewer assertion, not
an inferred GPS-to-line match.

Unresolved count includes ambiguous and unknown unassigned points, including invalid
positions. Explicitly reviewed transitions are separate resolved non-survey work;
they remain in membership and never enter Visits.

## Persistence and future QA invalidation

**SAVE REVIEW…** creates a new folder after staging and full verification:

```text
review_rN/
  README.txt
  review.sqlite
  intake/
    README.txt
    survey_intake.gpkg
    survey_intake_manifest.json
    sources/...
```

SQLite contains the complete planned snapshot, typed review state, decision history,
dispositions, segments, Visits, and relational ordered membership tables. JSON columns
preserve typed records; membership tables store individual exact Observation_ID links.
The nested standard Stage 3 package preserves source bytes where available and
independent native geometry/attribute snapshots. This is review persistence, not the
future completed-analysis export. No source file is edited.

Restore verifies the current Survey/plan and intake revision, archived native data,
source checksums, all relational memberships and a complete decision replay. An
incompatible plan revision, changed surveyor/mapping/normalized observation or changed
retained source is rejected. The fingerprint includes all Survey/plan records, source
records, recording metadata, raw index and normalized records, sorted by portable IDs;
dictionary/provider storage order is not meaningful. Failed or duplicate import
attempts do not change retained observations and do not alone stale review; their
ledger is preserved in the nested intake snapshot.

Snapshots have a `qa_input_digest` covering retained input, continuity parameters,
decision revision, current exact membership and Visits. Future QA must record that
token and treat any difference as stale. This stage does not calculate QA. Changing
intake, plans or externally supplied surveyor identity requires a new review run;
automatic decision migration would need separate validation and is not implemented.

Existing snapshot names are refused without modification. Save an edited revision to
a new name. Closing or opening another review with unsaved decisions asks before
discarding them. Concurrent editors, cryptographic signing, adversarial tamper-proof
auditing and cloud synchronization are outside this stage; verification detects
inconsistency, not a coordinated malicious rewrite of all records.

## Opening and using the workspace

Use **REVIEW ASSIGNMENTS…** in the Stage 3 `SurveyRecordingsPanel` after survey setup
and intake. This is still an additive Survey component, not a replacement menu flow
for the installed v0.1 dialog. In a development QGIS Python console, with the existing
Stage 3 `intake` object:

```python
from transect_navigator.ui.survey_recordings_panel import SurveyRecordingsPanel
survey_recordings_window = SurveyRecordingsPanel(intake)
survey_recordings_window.resize(1200, 650)
survey_recordings_window.show()
```

Choose a recording, inspect source-order and original/normalized time, and select
exact rows (Shift range or Command/Ctrl multiple selection). Selection highlights a
separate map display layer; **ZOOM TO SELECTED OBSERVATIONS** helps inspect it. Planned
lines are labelled by Transect_ID. Set plan/direction where applicable, reviewer and
reason, then act. Repeating an action on previously reviewed rows creates a revision.
Click a Visit row to inspect its exact membership. The unresolved-only filter does
not change membership. Invalid positions remain in the table although they cannot
be drawn on a map.

Save, close and reopen with **OPEN REVIEW…** against the same registered Survey/intake.
For a fresh process, the saved `planned_snapshot` SQLite row contains the full Survey
record (including planned WKB/CRS); reconstruct `Survey`/`PlannedTransect` records,
restore the nested intake using `load_survey_intake`, then `load_review`. Do not
re-register a different Survey creation/revision and pretend it is the original run.

## Validation and limitations

The focused fixture has 24 observations, 3 files, 4 recordings, two known surveyors
and one unknown surveyor recording. Independently authored expected review:
15 assigned, 5 ambiguous, 4 unassigned (2 transitions + 2 unrelated), 7 unresolved,
10 continuity segments and 6 Visits (4 forward, 2 reverse). No scientific inference
is made from these synthetic labels. See the sample README and `expected.json`.

Run focused tests under configured QGIS Python:

```shell
python3 -m unittest tests.test_review tests.qgis.test_survey_review -v
python3 -m unittest discover -s tests -t .
```

The new tests exercise real QGIS providers, ellipsoidal distances, native snapshot
integrity, no-overwrite persistence, tamper/staleness checks and Qt controls. Offscreen
mouse-button/selection and save/reopen tests do not constitute full interactive GUI
acceptance. Manually inspect map labels, selection visibility, panning/zoom, keyboard
range selection, file choosers and unsaved-close prompts in a real QGIS window.

Verified on 2026-10-07 with QGIS 4.2.3's bundled Python 3.12 on macOS:

- Pre-change: **332 passed, 0 failed, 0 errors, 0 skipped**, 15.634 seconds.
- Stage 4 focused: **35 passed**, 4.526 seconds (8 pure + 27 PyQGIS tests).
- Complete regression suite: **367 passed, 0 failed, 0 errors, 0 skipped**,
  16.933 seconds; process exit code 0. All original 332 tests are unchanged.
- `git diff --check` passed. The Qt font-alias fallback notice was nonfatal.

These timings describe the small automated fixtures, not survey-scale performance.
The QGIS environment used `QT_QPA_PLATFORM=offscreen`, the application bundle's
`PYTHONHOME`, `PYTHONPATH`, `QGIS_PREFIX_PATH`, `PROJ_DATA` and `GDAL_DATA`, with
`PYTHONDONTWRITEBYTECODE=1`. No release artifact or metadata was changed.

This utilitarian table is not virtualized. Native intake checks, fingerprints and
serialization scan retained data on review/save; memory and responsiveness for large
field datasets remain to be profiled. The focused fixture is not the later full
12-transect, 1,008-observation acceptance survey. No Stage 5 QA, project statuses,
association proposals, release ZIP or version increment is included.
